# 契约精简记录

本轮检查配置、安装、Provider、角色输出、Socket 通信、任务恢复、记忆、宿主服务、就绪、认证、音频/Live2D、架构和质量验证的主要边界。修改范围是重复的契约断言和验证工具，产品源码、配置、账号与运行时数据保持原有行为。

## 合并与精简

| 问题 | 修改 | 保留的保证 |
| --- | --- | --- |
| 全量后端门禁和 Qwen、RVC、生命周期专项重复执行 | 在质量目录声明三个专项组由 `backend-full` 覆盖 | 单独改动仍选择专项；全量执行仍有覆盖率门槛，静态和真实运行时检查保持独立 |
| 大门禁的缓存输入未包含它覆盖的小门禁输入 | 指纹沿 `covers` 传递合并目标、组件、上游和输入集，自动去重 | 被覆盖源码、配置或上游发生变化，大门禁缓存失效；复用现有循环校验和秘密过滤 |
| 日常 pytest 参数重复维护 | 统一过滤范围，用一个 YAML 锚点替代 26 处相同参数列表 | slow 和 integration 保持为显式验证；新增三个专项过滤范围前核对其当前文件没有这两类标记 |
| Qwen 真实 profile 的身份和默认超时重复抄写 | smoke、selftest、production 共用参数化契约检查；身份从宿主契约取得，检查应用超时预算覆盖服务预算 | 三个 profile 仍必须使用现有远程 Qwen；production 的默认能力关闭检查保留 |
| 部署测试重复检查 profile 选择和超时 | 部署测试只负责共享 Qwen 声明，profile 行为集中到配置测试 | 回退 Provider 仍复用同一 Qwen 声明；未引入第二份声线和模型定义 |
| Redis 测试绑死补丁版本和 Alpine、健康检查宽限期绑死秒数 | 检查官方 Redis 8 的固定版本标记，保留官方入口、模块、私有端口与持久卷检查；删除宽限期常量断言 | RediSearch、RedisJSON 与持久化要求不变；实际镜像和宽限期配置未修改 |
| 地图资源检查依赖质量文件中字符串出现两次 | 检查资源实际被前端运行输入和镜像输入匹配 | 资源变化仍能使测试与镜像身份失效，允许输入模式使用通配符 |
| 部署拓扑测试在影响计划中缺少实际执行目标 | 纳入现有生命周期专项组 | 修改部署契约测试时，规范验证入口确实执行该文件 |

## 保留的必要边界

- Socket 的字段类型、长度、UUID、身份关联和聊天黄金路径角色校验共同保护传输边界；编译后的类型与目录一致性检查继续保留。
- 角色回复结构、情绪枚举、亲密度范围和错误脱敏继续保留。
- 记忆主体/作用域、版本冲突、重复修改不增加修订，以及任务幂等与崩溃恢复语义继续保留。
- Qwen 身份、参考音频和宿主运行方式继续保留；Qwen 与 RVC 的外部身份字段不同，保持独立契约。
- 真实播放完成、任务关联、Live2D 行为、关闭功能不加载，以及必需服务就绪检查继续保留。
- 认证首次改密、权限限制和凭据持久化继续保留；部署环境的严格白名单是安全边界。
- 当前 production 的长期记忆模式仍为 `off`；本轮没有改变短期或长期记忆策略。
