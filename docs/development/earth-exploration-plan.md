# Animetta 地球探索实施计划

日期：2026-09-21。状态：待实施的详细设计。本次只制定计划，不开通计费服务，不修改产品行为。

## 1. 产品目标与已确认的设计

让 Animetta 和用户共同观察地球，根据用户的模糊记忆逐步缩小范围，认出熟悉的区域、湖泊、路口和道路。重点是画面体验、可理解的运镜与对话连续性。

核心场景：用户说“我想找我住的地方”，接着提供“好像上海”“大概青浦”“我记得淀山湖”等线索。Animetta 展示相应区域，在每次有意义的操作后停稳、解释原因、等待反馈。用户说“这条路我经常走”时，以点击或圈选确定指代，不自动认定住址。

已确认并保留：

- Cesium 三维地球是主要画面，卫星影像优先，真实地形与三维建筑按覆盖和授权启用。
- Live2D 位于地图中间偏右、下方贴齐页面底边，使用最近认可的放大比例。缩放窗口后保持构图，不遮挡主要目标和讲解文字，角色区域允许地图操作穿透。
- 一次有意义的镜头动作后再解释，不对每一帧、每一次细小平移进行讲解。
- 解释结束后默认等待 5 秒。在已选定区域内可继续观察，需要用户辨认或选择时保持等待。
- 用户拖动、滚轮、开始输入或开始说话时立即接管；“等一下”保持暂停，明确继续后才恢复。
- 正式界面使用自然对话与动态候选，不长期保留“上海、青浦、淀山湖”等写死的演示按钮。

第一版成功的标志：能以真实对话完成这条探索路径，镜头动作和用户看到的画面对应，关键选择不会擅自推进。第一版不要求在没有线索时从全球卫星图自动推断某个人的住所。

## 3. 数据源与接口决策

### 3.1 必须修正的前提

Google Map Tiles 官方政策将图像分析、机器解读和物体识别列为禁止的非展示用途。因此，不能按之前设想直接把 Google 三维瓦片截图交给模型分析。Google 可以作为可选的用户浏览层；视觉探索需要另有明确分析权限的数据源。此限制应在数据源能力中强制表达，而不是依靠提示词。[来源 S1]

当前 Esri 公开影像服务可访问，只证明原型能展示影像，不证明已获得任意截图存储、转发模型或商用权限。Google 的真实三维覆盖也不能从“全球地球”这一界面推导出来。上海、青浦、淀山湖分别实测并记录可用分辨率、覆盖类型和缺口。[S2、S3]

### 3.2 第一阶段选型

| 能力 | 计划选择 | 进入实施的条件 |
| --- | --- | --- |
| 渲染 | 继续使用已锁定的 CesiumJS | 通过正式构建和现有前端检查，不在本阶段追逐引擎升级 |
| 卫星展示 | 优先核实当前 Esri 服务对应的正式使用方案 | 明确账户、用途、归属展示、费用及网络可达性 |
| 三维实景 | Google 为可选增强层 | 受限 key、计费配置、目标地区覆盖实测；不进入模型视觉输入 |
| 地名搜索 | 优先选择允许与选定底图配合的托管 OSM 地理编码服务 | 上海中文名称和别名测试、服务条款、配额、报价通过 |
| 行政区与道路 | 使用带来源和版本的授权矢量数据 | 能获得多边形或道路几何、名称、坐标系；不能只凭人工点标签推导边界 |
| 高程 | 采用有明确使用权的地形服务 | 上海之外补一个山地样例，验证高度与点选位置 |
| 视觉分析 | 对同屏影像选择明确允许模型推理的供应商或自有影像 | 同时确认截图、传输、推理、保留期限与模型服务商条件 |

首版只实现一个默认搜索适配器和一个默认展示源。接口保留替换能力，不同时建设多套全球搜索服务。视觉源可以与展示源相同，但必须有相应权限；如果不同，应切换用户看到的底图并说明来源变化，不能让模型分析另一张图却声称在看当前画面。

不默认把公共 `nominatim.openstreetmap.org` 当成 Agent 的自动探索搜索后端。其公开服务有每应用至多 1 请求/秒、禁止自动补全和系统性查询等约束；如未来选择它，必须按其公开政策明确限定用途，不能沿用高频自动探索。[S4]

不默认把 Google Places 返回结果叠加到 Esri 底图。Google Places 的地图展示有供应商使用要求，若后续增加此适配器，须与实际地图组合一并核对。[S5]

### 3.3 P0 的具体交付

建立一份小型选型记录，每个服务记录：版本/核验日期、覆盖地点、坐标系、允许的用途、地图归属文字、密钥配置方式、计费单位、配额、实际请求结果、失败原因。至少覆盖上海、青浦、淀山湖、一个境外城市和一个山地区域。

输出一个可执行结论：选定首版展示与搜索组合，判断是否能开始视觉阶段。若高分辨率视觉源暂未落实，先交付自然对话加用户指认的探索版本，明确视觉能力未完成。低分辨率遥感图不能冒充可辨认住宅道路的影像。

## 4. 正式界面

### 4.1 产品入口

第一版放进现有 `/dashboard`，新增“探索”工作区，沿用登录与私密会话。无需新增正式顶层 HTML 入口。`earth-prototype.html` 在迁移完成前保留为演示参考。

直播地图是后续独立范围：若需要，再在唯一 `/live.html` 内组合地图场景，并由用户明确开启公开展示。Dashboard 的住处线索、精确点选和对话不能自动同步到直播或节目记录。

### 4.2 布局与信息

| 区域 | 正式内容 | 交互约束 |
| --- | --- | --- |
| 大幅地图 | 地球、影像、地形、少量候选与用户标记 | 移动中不堆叠新标签；关键目标保持在无遮挡视野 |
| 地图顶部 | 经过的区域、回到上一个观察点、数据源 | 路径来自真实导航历史，不固定六个站点 |
| 地图左下 | Animetta 当前一两句解释、继续提示、暂停 | 完整文字留在对话区，地图上避免长篇遮挡 |
| 地图下方偏右 | 现有放大后的 Live2D | 底部贴齐、无多余空隙、鼠标穿透、保留数据归属区域 |
| 右侧面板 | 当前范围、对话记录、文字输入、语音入口 | “你可以这样说”固定按钮改为首屏引导，进入会话即收起 |
| 临时候选 | 2–4 个区域或地标建议 | 由搜索或当前对话产生；选中才确认，不能假装模型看到了这些对象 |

视觉样式沿用 UnoCSS 与设计令牌。真实模型选择、调用状态和密钥放到设置或诊断信息，不混入普通探索对话。

## 5. 探索行为与等待规则

### 5.1 用户样例的正式行为

| 用户表达 | Animetta 的处理 | 何时继续 |
| --- | --- | --- |
| 我想找我住的地方 | 询问一个最有用的线索，例如城市或熟悉地标 | 等用户，不自动搜索全球住所 |
| 好像是在上海 | 将上海作为暂定候选，查询范围并缓慢靠近 | 可以展示上海概览，再停下来辨认区域 |
| 上海有哪几个区 | 查询真实行政区资料；地图按方位呈现少量区名，完整列表可展开 | 不依次飞遍所有区，也不自动选青浦 |
| 大概是青浦 | 将青浦加入暂定范围，保留上海关系与撤回入口 | 可以查看水系概览；没有湖泊线索就不擅自锁定淀山湖 |
| 是淀山湖，再放大 | 地名检索与范围校验后，先湖泊整体，再局部观察 | 已选择湖区内的观察可自动继续 |
| 这条路我经常走 | 保持视角，结合最近一次点选；缺少点选时请用户点一下 | 选中位置后询问行走方向或下一个地标 |
| 不对，是另一边 | 撤回相应假设，保留已确认线索，调整候选 | 不把旧路线继续执行完 |

“好像”“大概”表示暂定假设。地点被导航到，只证明镜头已到达，不能自动把它升级为用户确认的事实。

### 5.2 状态与职责

| 阶段 | 允许发生的事 | 退出条件 |
| --- | --- | --- |
| 待线索 | 用户输入、点选、查看已有候选 | 有足够明确的下一步 |
| 决策中 | LangGraph 用当前视图与线索选择一个动作 | 结构化动作通过校验，或提出一个问题 |
| 移动中 | 前端执行一个可取消的镜头动作 | 完成、取消或失败 |
| 画面就绪 | 镜头稳定、相关图层达到可解释质量 | 获得对应视图版本的就绪回执 |
| 观察中 | 读取地理资料；权限允许时分析当前截图 | 有结果、超时或被用户打断 |
| 解释中 | 字幕展示、TTS 播放、Live2D 表情与口型 | 实际播放结束；文字模式则阅读时间结束 |
| 等待反馈 | 静止画面、显示剩余等待时间 | 用户反馈，或满足自动继续条件后倒计时结束 |
| 等待辨认 | 保持当前范围，允许手动查看 | 用户明确提供线索或选择 |
| 已暂停 | 停止自动操作、播放与待执行动作 | 用户明确继续或给出新方向 |

这些是可观察的领域阶段，由现有 LangGraph 执行业务决策。前端只负责相机与输入等确定性状态，不另建一套独立智能 Agent 或后台轮询编排。

### 5.3 默认节奏

- 每次模型决策最多提交一个有意义的观察动作。长距离飞行的“拉远、平移、靠近”可作为同一个动作的连续分段，不分段讲解。
- TTS 模式从实际播放结束开始计算 5 秒。收到音频、合成完成或 socket ACK 都不能启动该倒计时。
- 纯文字模式按说明长度给阅读时间，第一版可沿用 7 秒作为默认值，再等待 5 秒；设置中可调整等待长度。
- 只有视图、用户线索和动作范围都没有变化，且下一步不需要用户作判断时，才允许继续。
- 默认自动推进最多连续 3 个观察动作或 60 秒，然后等待用户。此值是待体验调整的产品默认值，不是既有测量结果。
- 用户拖动、输入、语音起始、显式暂停、页面切到后台或工作区关闭，立即取消自动推进。语音被判为噪声也不悄悄恢复，保留“继续观察”。
- 网络恢复、重新连接或模型稍后返回，均不自动恢复旧动作。

## 6. 运镜、加载与指认

### 6.1 运镜规则

保留北向上作为默认朝向；同区域内保持朝向连续。远距离先拉远建立空间关系，再横向移动、最后靠近；邻近观察用小幅平移或缩放。第一版不自动绕目标旋转，避免视觉迷失。

动作输入表达“展示这个区域”“靠近这个标记”“沿这段河流观察”，而不是让模型每秒生成鼠标拖拽。镜头执行器根据目标范围、当前位置、遮挡矩形和慢速偏好生成轨迹。[Cesium 相机接口 S6]

建议初始参数：邻近移动 3–5 秒，跨区域 6–10 秒；具体由距离与缩放跨度决定。控件动画仍遵守项目的 150/200/300ms，镜头旅行是用户要求的多秒空间导航。上述时长是设计值，未经性能测量。

### 6.2 就绪与失败

动作完成回执必须区分 `arrived`、`ready`、`degraded`、`failed`、`cancelled`。相机停止并不等于影像清晰，globe 就绪也不代表可选三维图层就绪。按当前启用图层聚合状态并记录错误，避免用所有远景请求全部结束作为唯一条件。

允许在已加载范围内观察，不允许把持续模糊或缺失区域当作细节证据。默认等待上限 20 秒，超时停止自动推进并说明画面未加载完成。恢复后先重取当前视图，不重放过期队列。保持已有可用底图，失败时不突然跳回全球视角。

### 6.3 点选与画面一致性

- 指认包含 `view_revision`、屏幕标准化坐标、视口尺寸、设备像素比、相机姿态与点击得到的地理坐标。
- 在三维建筑/地形模式下，优先使用渲染深度或地形射线拾取；只有椭球模式才使用原型的 `pickEllipsoid`。不可把椭球交点称为建筑表面位置。[S7]
- 点选时立即冻结该指代。若之后镜头移动，旧截图中的“左边那条路”不能套用到新画面。
- 道路名称来自独立地理数据匹配，记录来源与匹配距离；无匹配则只称为“你点的位置”。
- 区域边界、检索结果和影像必须带坐标系。内部统一 WGS84；供应商返回其他坐标系时在边界显式转换并用地标对齐验证，不通过手工偏移解决错位。
- 若模型按像素圈出疑似目标，返回候选标记并请用户辨认，不自动确认为真实道路、住宅或用户位置。

### 7.2 最小工具集合

| 工具（拟定） | 输入 | 结果及边界 |
| --- | --- | --- |
| `earth_search` | 地名/地标、可选当前区域、候选上限 | 返回带来源的候选、范围、坐标系；不自行移动镜头 |
| `earth_observe` | 当前视图版本、观察问题 | 返回可用地理上下文与许可允许的视觉观察；无视觉权限时明确只用结构化数据 |
| `earth_navigate` | 目标候选/区域/标记、镜头意图 | 返回动作 ID 与执行状态，最终以客户端回执作为到达证据 |

暂停、继续、用户点选和返回上一个观察点优先作为确定性会话命令处理，不为每个按钮再增加 LLM 工具。第一版不支持模型传任意脚本、第三方 URL、逐帧拖拽或长动作队列。

### 7.3 会话与协议

继续使用既有 `session_id`、`conversation_id`、`task_id`。地图新增 `action_id`、`view_revision`、`control_revision`，分别标识一个动作、一个实际视图和一次控制权变更。

拟定事件：

| 事件 | 方向 | 核心内容 |
| --- | --- | --- |
| `earth:command` | 服务端到操作者页面 | 导航/标记动作、动作 ID、预期视图与控制版本 |
| `earth:result` | 操作者页面到服务端 | accepted/arrived/ready/cancelled/failed、实际视图版本、失败原因 |
| `earth:context` | 页面到服务端 | 当前视图、数据源、可见范围、就绪质量、用户指认；只在有意义变化时发送 |
| `earth:control` | 页面到服务端 | 暂停、接管、继续、输入开始、工作区退出 |

具体名称须通过现有契约生成器核对，但字段含义与行为必须保持一致。ACK 只确认收到消息，不作为动作已经完成的证据。

每个会话只有一个操作者页面拥有相机执行权。其他页面只读或显式接管。所有回执核对认证用户、会话、动作与版本，不接收另一个客户端的就绪事件。

用户接管在本地即时生效，先取消相机和音频并递增 `control_revision`，再通知服务端。晚到的模型输出、TTS 和动作回执必须因版本过期被丢弃。重连恢复最近状态但保持暂停，不重放未完成动作。重复 `action_id` 只返回既有状态，不再次飞行。

### 7.4 状态保存

LangGraph 负责会话中的目标、暂定范围、已确认线索、候选、当前动作和等待原因；Pinia 负责对应 UI 投影及实时相机状态。前端不另存一套独立“智能计划”。长等待用现有图的可恢复机制处理，不持有一个长时间睡眠的工具调用。

保存观察点时记录相机姿态、范围和用户线索，支持“回到刚才那里”。原始截图、精确住处标记默认只在当前私密会话临时使用，设定过期清理，不自动写入 memory/v2。用户明确要求“记住这个地方”时才走现有记忆规则。

## 8. 视觉理解

### 8.1 一次观察的输入

前端在镜头稳定、允许分析的图层就绪后采集一次视图，连同截图时间、`view_revision`、镜头参数、地理范围、数据来源、质量、点击位置发送给模型。截图以地图为主体，角色和对话 UI 不成为识别对象；需要保留的归属信息一起传递。

正式采集不沿用“每帧截图并发送”的方式。默认一个观察动作一个最新帧，长边先限制在 1280 像素、压缩后上限 1 MiB，具体值在质量测试中调整。中间过程帧不发送。未获得权限的数据源不得通过隐藏图层、第二个 canvas 或截图转存绕过限制。

观察结果应分开表达：

- 用户提供的线索，例如“经常沿这条路走”。
- 数据源确认的名称与几何，例如道路或行政区记录。
- 画面可见事实，例如“岸边有一个十字路口”。
- 待确认假设，例如“这可能是你记得的桥”。

当前画面变化后，旧结果可以留作历史，但不能驱动新视图上的精确点击或导航。模型看不清时请求靠近或询问，不补造建筑名、道路名和用户住址。

### 8.2 多模态接入验证

先选择当前配置中真正支持图像输入的 Provider，用一张自有测试图验证：请求中确有图像块、模型能答出图像信息、原始图像不会落入公共对话/长期记忆。随后才使用获授权的地理影像。

尽量复用既有 messages 能力；如果现有类型或 Provider 丢弃图像块，按项目 Provider 模式补齐。不能以 SDK 接受字典、模型名称含 vision 或 HTTP 200 作为支持多模态的充分证据。

## 9. 语音与 Live2D

使用现有 ASR、宿主 Qwen TTS 与共享音频播放器。文字输入先交付，语音是下一阶段，不通过新增 Qwen 容器或新的音频播放链路实现。

字幕与语音对应同一 `task_id`。真正开始播放后再启动讲解口型，播放结束后关闭口型并进入等待。取消应同时作用于播放队列、口型与过期解释。Live2D 在移动中保持轻微待机，观察时可用已有思考表情，不为每个相机帧生成动作。

浏览器内部保留可验证的播放记录：task_id、播放开始/结束/取消时间、播放计数和错误。界面无需显示这些诊断字段。没有实际播放证据，不报告“她已经讲完”。

| P2 真实对话闭环 | 搜索工具、LangGraph 单步动作、会话/版本/ACK、动态候选、边界与反向辨认 | P1 + 搜索可用 | 文字完成上海—青浦—淀山湖—用户指认，非上海案例也能工作 | 2–3 天 |

| P5 联调与交付 | 真入口验收、性能基线与调参、断网/重连/多窗口、更新演示 PPT | 已纳入发布的阶段 | 达成验收矩阵，有可复现证据和回退方案 | 1–2 天 |

每个阶段采用小批次提交。当前请求授权的是计划准备；这些开发阶段尚未执行。首先可实施的是 P0 与 P1。

## 11. 验收矩阵

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| A01 | 初次进入 | 真实地图、角色、输入可用；角色底部贴齐；核心操作不依赖演示按钮 |
| A02 | 上海到青浦 | 地理搜索结果有来源、候选区域正确，镜头保留空间关系 |
| A03 | 无用户反馈 | 已选区域内按节奏继续，但不会把沉默当作选区或住址确认 |
| A04 | 地图拖动/滚轮 | 当前动画、待执行动作与倒计时立即取消；无旧动作回弹 |
| A05 | 输入与语音打断 | 从输入起始生效，过期模型回复和 TTS 无法恢复旧动作 |
| A06 | 指认道路 | 模型得到正确的同一视图点选；无道路数据时不虚构名称 |
| A07 | 错误线索与撤回 | “不是青浦”能撤回假设；返回历史观察点不只是按固定索引减一 |
| A08 | 图层慢/失败 | 停止自动推进，保持可用画面；不把模糊区域当作视觉事实 |
| A09 | 重复消息和重连 | 同 action_id 不重复飞行；重连保持暂停；异会话不能控制相机 |
| A10 | 图像输入 | 模型实际收到允许分析的最新画面；Google 层无法进入视觉请求 |
| A11 | TTS 与口型 | 实际播放及结束证据齐全，倒计时从结束后启动，取消后口型复位 |
| A12 | 正式页面 | 真实 URL 的服务进程与前端资源指纹一致；不以 Vite 原型通过代替正式入口验收 |
| A13 | 大小窗口 | 1280×800、1600×1000、1920×1080 下角色/讲解/候选/归属无遮挡且地图可操作 |
| A14 | 泛化 | 除上海样例外，至少一个未写入固定路线的城市和一处自然地貌可完成搜索与观察 |
| A15 | 私密隔离 | 精确点选、截图与住处线索不进入直播、公开回复或默认长期记忆 |

性能验收先记录当前原型的实际基线，再冻结优化目标与预测，在相同硬件、窗口和路线条件下比较。初步目标为暖缓存地图与 Live2D 同屏时多数帧维持 30 FPS 以上、本地打断 p95 不超过 100ms；这些是待实测校准的目标，当前没有达成声明。

建议每种关键布局运行 5 次固定路线，记录冷/暖缓存、帧间隔分布、长帧、截图耗时、模型耗时、瓦片就绪时间、首段音频延迟、取消延迟和失败次数。网络与模型耗时分别报告，不用本地动画帧率掩盖等待。普通开发期间不反复跑性能基准，集中在 P5。

## 12. 验证、运行与回退

- 单元测试重点保护控制版本、过期结果丢弃、自动继续条件、候选来源和点选坐标。浏览器测试只覆盖运镜、取消、可见布局、真实指认与播放证据。
- 每批精确列出修改文件，先生成 affected 计划，纠正未知路径或不合理的全后端映射。最终差异冻结后执行一次规范验证；不跳过规划器选中的组。
- 日常源码实现不启动 Docker。P5 在用户要求的正式 URL 验收时，确认实际进程与资源指纹，通过现有运行生命周期更新，然后回到同一 URL 验证。
- 发布前准备一个功能开关，禁用探索后恢复原有 Dashboard；搜索和模型超时不能拖垮普通聊天。退出工作区销毁 Cesium、Live2D 实例及订阅，取消未完成动作。
- Cesium 的正式 Workers、Assets、Widgets 使用锁定版本随构建发布，不引用生产环境的 `/node_modules/`。Provider 配置不直接写进组件。
- 地图浏览器 key 采用来源/API 限制，服务端检索 key 留在后端。按供应商要求限流和缓存，不批量下载全球瓦片。
- 费用在 P0 根据选定服务估算，区分地图会话/瓦片、搜索、模型图像输入与语音；设置应用请求预算及供应商配额。未获得报价与调用实测前不填写虚构的月成本。

本计划是内部 Markdown 设计文档，不参与产品、测试或发布契约。本次文档交付按仓库规则仅做差异与提交钩子检查；上述运行、功能与性能验收都是未来实施任务。
