# 核心部署精简测量契约

冻结日期：2026-10-11。原实现版本：`b422c70a`。本文件在产品源码改动前创建；预测与条件不随测量结果回写。

## 核心与质量

保留角色对话、Live2D、记忆 v2 和现有 Qwen TTS 声线。默认文字输入，语音输入、唱歌、Minecraft、搜索和地图等按需启用。保留 LangGraph、认证和 Redis 持久检查点。Qwen 位于 Windows 宿主机 8767，RVC 位于宿主机 8769；普通应用重启复用已就绪的 Qwen。

质量验收覆盖真实 `/live.html`、`/dashboard`、登录、所选 LLM 的真实回复、记忆身份隔离及连续性、Qwen 身份和关联任务的实际播放。不得以 Mock、收到事件或合成成功代替真实播放。

## 测量条件

- 同一机器、Python 3.13、锁定 uv、同一依赖源和相同模型身份；记录版本、资源、原始命令与阶段耗时，密钥不落盘。
- 安装使用隔离虚拟环境；冷安装使用任务专属空 uv 缓存，暖安装复用该任务缓存。冷、暖各至少 3 个独立样本，不清空用户缓存或改动工作区开发环境。
- 应用启动使用规范生命周期与相同 profile。分别记录应用进程冷启动、复用模型的应用重启、模型冷加载和 HTTP 就绪；应用冷启动不冒充机器重启或冷缓存构建。
- 可获得的启动样本冷、暖各至少 3 个；安装、下载、构建、模型加载、首轮回复和播放分别计时。冻结实现的原始样本完成前不改动对应执行输入。
- 记录实际安装包、安装体积、镜像体积、应用 RSS、GPU 空闲量与进程归属。报告每项样本数、中位数和范围；无法测得或环境阻塞的项明确标记，保留失败，不以预测补数。
- 不停止无关进程、不清理 Docker／用户缓存或运行数据。构建和模型生命周期只有一个执行方。基线与改造后使用相同缓存定义和场景；不可比数据单独报告。

## 修改前预测

1. 核心依赖闭包和实际安装体积下降；预期去掉 Bilibili、社区搜索及其专属间接依赖，具体幅度由实测决定。
2. 默认计划不包含 RVC 的启动／预检；关闭可选能力时不导入实现、不初始化模型或探测外部服务。无 RVC、本地 ASR／VAD 或 Minecraft 环境仍能完成核心场景。
3. Qwen 已就绪时，应用重启不重载其模型，宿主 PID 与声线身份保持；应用就绪时间预期改善，但不预报未经测量的百分比。
4. 主应用没有 Torch／Transformers／训练包；保留现有核心质量和明确的缺失能力错误，不能以静默降级获得收益。
