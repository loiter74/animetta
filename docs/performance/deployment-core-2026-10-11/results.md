## 已实现的边界

- 唯一 canonical profile 增加类型化能力开关，默认关闭语音输入、Bilibili、唱歌、Minecraft 和地球探索；production 直接使用原 Qwen 合同，关闭产品工具。
- 关闭麦克风时，仅解析和初始化 LLM/TTS，不访问 MIMO 密钥；ASR/VAD 在 `/ready` 中明确为 disabled，不冒充 ready，也不阻塞必需能力。改变能力组成需要重启。
- 原 ProviderRegistry 与工厂保留；VAD 只导入选中的实现，唱歌流水线及地球控制器延迟加载。关闭事件返回 `CAPABILITY_DISABLED`；核心对话、Live2D 与记忆入口保持。
- 宿主服务计划由同一 manifest 选择：默认只有 Qwen 启动与预检，启用唱歌才加入 RVC；显式宿主操作与 `anima-down` 的保留语义不变。
- 核心 requirements 移出 Bilibili 和社区搜索，通过 uv extras 及生成规格单独安装。开发规格包含 extras，以继续验证原功能。
- 后台将关闭的 ASR/VAD 显示为“未启用”，保留独立的配置／实际身份展示。未就绪的必需 Qwen 仍会失败，未放宽身份与认证检查。

部署方法见 [核心安装与可选能力](../../development/core-deployment.md)。Redis、LangGraph、记忆 v2、Qwen 模型和声线均未替换；地图／Electron 构建资源与神经模型环境进一步分拆留到后续阶段。
