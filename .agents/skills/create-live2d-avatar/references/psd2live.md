# PSD2Live 原生制作与导出经验

以下来自 Windows 上 PSD2Live 3.4.5 的实际建模。先核对当前版本、官方接口与模型状态；工具修复后不继续套用旧版补丁。

## 工具定位与事务

- 已验证安装参考：`C:/Users/30262/AppData/Local/CodexTools/anima-whale-maid-v1/portable`。官方源码在相邻 `source/`。这是本机工具位置，不是新角色输出目录，也不保证其他机器存在。
- 本机原生 MCP 曾使用 loopback HTTP `/mcp`。先从当前编辑器配置确认地址、会话和可用工具；鉴权仅在调用进程中读取，不打印、写入技能或提交凭据。启动前核对进程完整命令行，复用合适实例。
- `workspace_get_operation` 查询确切操作的 `request_schema`；`workspace_inspect` 检查参数、对象、层、预览。大响应只保存本地并提取所需字段，避免输出整套 schema 或图像编码。
- 编辑使用最新 `state`、`project_id` 与独立 `request_id`。`workspace_apply_edits` 可原子提交一组相关编辑。请求内容改变就换请求标识；超时且已有任务句柄时继续等待同一任务，不能重复发起。
- 结构性修改前 `save_as`，导出到候选目录。导入修复后的当前工程使用 `project` 的 `import_cmo3` 并明确导入方式；先保存，再取新鲜状态。素材切分或新增贴图后的恢复优先使用独立 `NEW` 导入，不能默认 `REPLACE`；后者需先证明现有 atlas 与待导入资源不会重复。不要重新打开较早工程而丢失新绑定。
- `.psd2live` 是 ZIP 工程，`rig/objects/*.bin` 为原生二进制数据。需要程序化修复时优先官方 `Cmo3.read/write`、图编辑 API 与 `RigIrBinary.Reader`，保留资源和未修改字段，不能按文本猜格式。

## 坐标与局部增量轴

- 原画／画布为像素坐标，X 向右、Y 向下；导入工程的 parent-local 和 Core 坐标不能与像素坐标混算。记录对象范围、父级和单位后再变形。
- 已验证 `rig_deform` 的 `selection.rect` 是相对目标范围的 `[uMin,vMin,uMax,vMax]`，不是 X/Y/宽/高；`arc.root/tip` 和 `rotate.pivot` 也是操作起始对象范围内的归一化坐标。
- 原生 3.4.5 的 `author_axis(kind=blend_shape)` 曾因自动创建空坐标关键帧失败。该版本已验证替代方案是原子执行 `parameter_create(kind=blend_shape)` 与两端 `rig_deform`，保留自动创建的中性增量形态。未来版本先核对实现。
- 几何门禁失败时定位具体三角形、选区权重与参数组合。例如选区边界只拉动三角形两个顶点时，应调整边界／过渡或网格，不能盲目缩小所有动作或绕过门禁。
- 对新轴验证默认值、端点、插值与组合，并从实际 MOC 观察顶点变化；同名参数存在并不表示已绑定。

## 已验证的导出问题

### 口腔存在但看不见

旧版导出器会清理静态参考姿势中的零面积三角形。闭嘴关键帧若把口腔完全压成共线网格，可能导出顶点尚在、三角形索引为零的口腔。

1. 检查实际 MOC 的口腔索引、透明度、贴图页和绘制顺序，再判断问题来源。
2. 闭嘴关键帧保留少量正面积并设置透明度零；保持默认口型和半开／全开形状符合设计。
3. 如果拓扑已丢失，改变形状不会重新生成索引。该状态下 `layer_mesh_rebuild` 曾因无效网格迁移失败，`canvas_topology connect` 也不能从零索引创建三角形，停止重复尝试这两条路径。
4. 从可信原工程恢复拓扑前，核对顶点数量、UV 顺序与坐标关系。用官方 API 恢复相应索引／编辑边，证明其他网格、资源与关键帧未改变；不能照抄别的角色的点数和索引。
5. 再导出并用 Core 检查闭嘴、半开、表情静息开度与全开，最后查看实际口腔贴图。

### CMO3 与 MOC 静态姿势不一致

已遇到 CMO3 在本次导入之前就保存了错误的肩颈补底静态坐标，而旧 MOC 的画面正确。按每个网格对比默认顶点才能定位，不应直接归因于父级绑定。

需要恢复时，以可信 Core 的 origin／pixels-per-unit 还原画布坐标，使用官方 API 同步源坐标、静态关键帧和编辑点。按模型单位记录浮点残差，并核对有效三角形、UV、层级及其他网格；删除确切零面积三角形与删除有效拓扑要分别计数。

### 贴图错页或全为零

旧版重新导出导入模型时曾产生 `NoAtlasPageBound`，MOC 贴图页号全零，而旧 UV 与贴图内容仍需原来的页号。

- 保留已验证的原贴图与 UV，为当前模型按 ArtMesh ID 建立页号清单；不要直接用新导出的重排贴图替换成品。
- 示例修复器是 `frontend/public/live2d/whale-maid-v1/source/restore-texture-pages.cjs` 及相邻 `texture-pages.json`。它属于该模型，不能直接用于其他角色。
- 优先修复官方导出链；确需同格式页号修复时先验证 MOC 版本、节边界、实际 drawable 数量、ID 与页号范围，修复后重新通过 Core 一致性和贴图实渲染验收，不能盲写固定偏移。

### 重复 atlas 槽与丢失 CMO3 节点

3.4.5 的 `REPLACE` 导入曾把旧页与相同的导入页重复加入 PuppetAtlas。随后素材切分只生成实际新页，保存或重放却按重复槽数回写索引，造成实际 PNG 数量与页槽数量不一致。CMO3 转换还可能直接略过超出范围的素材节点；此时文件结构已经不完整，不能只修 MOC 页号。

1. 对照完整可信工程的 ArtMesh ID 集合、实际 PNG 数、atlas 槽数、页号范围、逐页内容哈希与 UV；先分清仅页号错误，还是源节点已丢失。相同尺寸或文件名不能证明贴图相同。
2. 已丢节点时，从保存的完整 `.psd2live` 用官方 loader 和编辑日志恢复，不以残缺 CMO3 继续绑定。用官方 API 导出完整候选，再经独立 `NEW` 项目验证；不扫描历史二进制并拼凑未知版本。
3. 在恢复候选上比较默认、中间开度、端点及父级组合，核对几何、UV、透明度、绘制顺序和 mask。首次素材编辑成功后立即保存并检查完整导出，再继续新增图层。始终保留原项目，不用旧版整体工程覆盖新绑定。

## 播放器与分辨率

- pixi-live2d-display 的 SDK 自动呼吸曾叠加头部角度，因此“Idle 没有头部曲线”不足以证明不会自动摆头。按模型配置核对额外呼吸驱动及动作写入来源，再关闭或调整对应层。
- 同一参数由 Idle 与 Physics 持续写入会互相覆盖。先列出两者输出参数，再选择唯一持续驱动方式；表情静息口型与说话开合单独合成。
- 物理文件的 `Meta.Fps` 不保证播放器实际固定步进。当前 SDK 曾按每渲染帧更新粒子；需要固定步长时替换其唯一物理阶段，从实际 rig 推导输入／输出，保持二者不重叠。显示插值不能回灌模拟，暂时改写的输入须恢复，后台恢复须限制追帧；以实际 SDK 的多帧率姿态证明和浏览器画面验收，不能另加第二个物理 writer。
- 检查闭眼过渡中可见眼白三角形的翻折，完全闭眼的隐藏网格和中性姿势正常不能代替这一项。
- 4K 是输出契约：实际画布与截图均为 3840×2160。侧栏截图可能只是缩放 JPEG；以文件格式与实际尺寸验收。原画、贴图和画布分辨率分别记录。
