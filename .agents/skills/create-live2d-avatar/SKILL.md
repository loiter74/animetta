# 立绘 Live2D 化

交付可编辑原画、原生工程和实际可播放模型。参数名称、生成插画和网页分辨率不能独立证明建模质量。

## 续作与准备

- 先读取已有任务记录和源文件，复用已确认的角色、服饰、比例、发型与差分；新角色不照搬鲸鱼女仆的设计、参数数量或摆动幅度。沿用已有授权，不重复索要已确认的选择。
- 区分原画、方向稿、分层 PSD、编辑工程与运行文件；先检查文件类型和实际像素尺寸，不能把压缩工程当 JSON。为当前模型选择独立目录和模型标识，保留原始素材及发布前版本。
- 建模或修接缝前按需读取 [官方流程与现成能力复用](references/production-workflow.md)。先核对拆件、补画和工具已有功能；需要分别运动的皮肤、头发、衣料混在同层时先修原画，不以自定义 UV、全局胶合或增加组合关键帧代替拆件。
- 核对当前原生编辑工具及接口。使用 PSD2Live 时按需读取 [原生工具与导出经验](references/psd2live.md)，不凭记忆猜操作或请求字段。

## 原画与分层

1. 以已确认原画为身份参考，按需使用 `imagegen` 技能补画、修脸或制作差分，先查看本地参考图。生成图先作候选，检查完整头顶、手脚、透明边缘和衣领衔接后再替换源素材。
2. 分层服务于实际可动需求：头脸、前后发束、眉、左右眼白、虹膜、高光、睫毛／眼皮、闭眼、口腔与嘴唇、躯干、袖臂、手、服饰边缘及角色特有部件。需要独立运动的部位应有足够网格和遮挡补画；不能只增加参数名称。
   保留带蒙版／补画层的拆件母版与每个部件合并为单层的导入 PSD。逐层隐藏检查材质归属及遮挡补画，再检查默认组合；此阶段失败就返工拆件，不继续绑定。
3. 标准表情与用户要求的特殊表情保留同一角色和服装。嘴部准备闭嘴、半开和全开状态，眼睛检查半闭状态；只在完全隐藏帧检查网格会漏掉过渡翻折。

## 绑定与动作

- 先确定根／躯干／头部／局部部件的继承关系和默认姿势，确认肩颈接缝与被遮挡区域连续，再逐件绑定。发根、肩、袖口、腰等连接处固定，运动向末端渐变。
- 优先复用可用的原生模型模板、变形器、网格编辑和检查工具；Glue 用于两个网格的实际重合接缝。工具导出存在已复现缺陷时先做最小对照，再选择受限恢复或换用兼容工具，不能把格式补丁推广为常规制作步骤。
- 按需求绑定头身角度、眨眼、视线、眉、口型以及发束、衣物、附件。对已有网格增加局部形变时保护相邻脸部、手与腿；整体拉伸头部不能替代面部重画。
- 每批保留可恢复工程并保持原生单写入者。异步任务继续轮询原任务；失败先定位坐标空间、拓扑或接口根因，再用新请求标识提交改过的请求。
- 每条新增轴用真实 Core 检查两端和中间值：应有真实顶点位移、只影响目标范围、默认姿势无意外漂移。对会叠加的轴检查组合，记录新增翻转、退化和非有限坐标。
- 待机、物理、表情与口型明确各自写入的参数，避免同一参数被多个持续驱动器争写。用轻微的呼吸和局部联动组织动作；没有用户需求时不靠头部反复旋转营造全身运动。

## 导出与验收

1. 导出编辑工程及 `.moc3`、`.model3.json`、贴图、显示信息、动作、物理、表情文件。核对所有引用、素材来源、文件大小与模型标识；不要用本次导出覆盖唯一可恢复源文件。
2. 使用实际 Cubism Core 验证一致性、参数范围、可见网格的三角形、贴图页号、UV、层级和默认顶点；对照导出前后结果。眼睛和嘴从闭合到完全打开都要检查，不能只凭导出成功判定通过。
3. 在产品实际入口加载成品，验收全身、脸部放大、标准／特殊表情、说话口型、眨眼、局部联动及接缝。生成方向稿不能作为模型运动证据；纯 Skill 整理或离线计划不启动编辑器和浏览器。
4. 分别记录原画分辨率、贴图尺寸、画布像素和截图尺寸。4K 输出须实际得到 3840×2160 画布与同尺寸图像；不能由此宣称低分辨率原画已成为原生 4K 素材。

## 接入 Animetta

- 模型能力与情绪映射放在模型配置；公开当前回合情绪经共享表情控制器选择已有差分。手动预览优先，恢复自动时采用最新情绪；口型独立驱动。
- 复用 `/live.html` 和后台“立绘调试”，调试状态不进入直播画面，预览命令只影响隔离的静音预览。
- 遵循仓库验证和发布流程。交付时说明已验证部件、真实输出尺寸、证据位置和未完成项；商业级精修要依据分层、过渡形态、组合姿态及实际画面验收，不能仅用参数数量作结论。
