# 运行阻塞与恢复

仅在运行任务中断、无进展或失败时读取。沿用生命周期已有的 run、租约、截止时间与证据，不另写轮询器或恢复状态机。

## 先判断任务是否真的阻塞

- **中断或用户再次说“继续”**：先核对原 run 的终态、实际后台进程及落盘结果。成功步骤直接进入下一步；仍执行中的任务按原 run 续接；失败任务先诊断，不自动重跑。
- **外层日志为空或只显示 `in_progress`**：先读命令 receipt、实际子进程与最近更新时间；构建可读对应 BuildKit history 日志，应用可读生命周期保存的完整 stdout／stderr。只有外层日志未刷新不能判为卡死。超过该阶段约定的无进展窗口时定位等待点，不启动第二个构建。
- **停止命令已返回，但目标进程仍在**：核对 PID、创建时间、完整命令行及子进程；在现有停止截止时间内等待精确进程退出，超时才失败。停止完成不等于模型已卸载，端口关闭也不能代替进程证据。
- **日志计数为零**：确认是否只采集了 stdout；优先读已保存的完整日志。不能用空日志宣称“未初始化”或“只初始化一次”，也不为补日志证据先重启实例。

进展更新给出当前阶段、最近证据和下一动作；结果已落盘就及时交付，不把工具返回窗口或反馈间隔相加当作真实运行时间。

## GPU 或桌面进程阻塞测量

1. 核对占用进程归属和实验已声明的隔离条件。普通桌面进程不能仅因出现在 GPU 列表中就自动被终止；冻结测量规则触发暂停时也不能临时放宽规则继续同组样本。
2. 本任务创建的 UI／浏览器辅助进程，优先通过其所属工具的正常关闭或 reset 释放。用户应用有窗口时尝试正常关闭；有保存提示则保留内容。
3. 无可关闭窗口且必须结束用户进程才能继续时，一次性说明准确进程、证据和可能丢失的未保存内容，请求该动作的授权。授权到达后重新核对进程身份，避免 PID 复用；结束并确认占用消失后继续，不再次索要“继续”。
4. 驱动或退出判定确有缺陷时，保留原样本，修订后重新冻结驱动并补齐同条件基线；不得悄悄改变守卫来保留不可比样本。

## Docker Desktop 或迁移失败

- 先区分产品启动失败与 Desktop／存储故障。读取实际版本、官方命令帮助和错误日志；需要界面时确认窗口可定位、桌面未锁定，不能反复点击遮挡坐标。
- 一次失败后，只有失败原因或环境已改变才重试同一迁移动作。工具返回码、复制完成与设置生效分别检查；目标出现 VHDX 不代表数据盘已切换，须核对实际设置与实例身份。
- 恢复优先使用当前版本支持的正常 stop／start。若错误态需要强制停止、临时 IPC 目录恢复等额外动作，先核对已有授权、精确进程退出和目标路径边界；不把历史成功的修复命令自动套到新故障。不得因此手改迁移设置、删除 VHDX、重置 Docker 或清除用户缓存。
- 受支持路径仍失败且任务要求固定版本时，保留失败证据、备份及原布局，标记该场景缺测，继续不依赖迁移的实验。升级或手工迁移不能伪装成同条件对照。
- 故障恢复、迁移、人工等待与性能样本分别记录。修复后单次正常停启成功不覆盖此前失败，也不等于通过电脑重启稳定性验收。
